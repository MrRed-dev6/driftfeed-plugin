# Скрипт подписи TikTok

Плагин не подписывает запросы сам: он передаёт JS в движок клиента
(`ProviderContext.evalJs`) и забирает готовый URL.

Скрипт, который там выполняется, — это JS самого TikTok, который считает
параметры подписи (`X-Bogus` и то, что придёт ему на смену). Он:

- **не написан нами** и не может быть написан «с нуля»;
- **периодически меняется** — когда TikTok его обновит, старый перестанет
  давать валидную подпись;
- **кладётся в плагин ресурсом**, а не в клиент, чтобы обновляться выпуском
  новой версии плагина без релиза приложения.

## Куда положить

```
plugin-tiktok/src/main/resources/tiktok/webmssdk.js
```

Gradle упакует его в jar, а `tools/build-plugin.sh` перенесёт в итоговый
`provider-tiktok.jar` рядом с `classes.dex`.

Пока файла нет:

- `Signer.available` = `false`;
- `TikTokProvider.capabilities` — все `false`;
- клиент покажет источник как «ничего не умеет», а не будет падать.

## Что от него требуется

После выполнения скрипта в глобальной области должна быть доступна точка
входа, которую найдёт шим из `Signer.BROWSER_SHIM`. Шим ищет
`globalThis.byted_acrawler.frontierSign(url, userAgent)` и добавляет
`X-Bogus` к URL.

Если в новой версии SDK точка входа называется иначе — правится одна функция
`__tiktokSign` в `Signer.kt`, а не весь плагин.
