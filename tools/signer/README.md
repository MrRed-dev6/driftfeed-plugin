# signer.js — скрипт подписи `X-Gnarly`

Здесь лежит исходник, который плагин исполняет в движке клиента, чтобы
подписать запрос к `/api/recommend/item_list/`. В dex он попадает строкой в
base64 (`SignerScript.kt`), собранной из этого файла.

## Что это

Сборка [`abogus`](https://www.npmjs.com/package/abogus) 2.1.1 — MIT, © 2024
sobird, текст лицензии в `LICENSES/abogus-MIT.txt`. Это чистый JS без
зависимостей: считает `X-Gnarly` так же, как браузерный SDK TikTok.

От пакета остались только нужные правки, и все они механические:

1. `export{...}` в конце `dist/index.js` заменён на `return {...}` — чтобы
   модуль стал обычным выражением и его можно было обернуть в функцию.
2. Сверху добавлены заглушки `TextEncoder` и `TextDecoder`: в QuickJS их нет,
   а код создаёт их при загрузке (`new TextDecoder("latin1")`). Кодировщик
   реализован честно, декодер — пустой: он нигде не используется по делу.
3. Всё обёрнуто в `var __signer = (function(){ ... })();` — так скрипт грузится
   один раз, а дальше вызывается `new __signer.XGnarly().sign(query, "", ua)`.

`crypto` не подставляется: `abogus` проверяет его наличие и откатывается на
`Math.random`. Для подписи этого достаточно — она всё равно одноразовая.

## Как пересобрать

```bash
mkdir -p /tmp/ab && cd /tmp/ab
npm pack abogus@2.1.1 && tar xf abogus-2.1.1.tgz
# далее — те же три правки, что описаны выше (export → return, заглушки,
# обёртка в var __signer)
python3 tools/make-signer.py     # из корня репозитория
```

## Как проверить

Проверять надо **тем же QuickJS, что в клиенте**: `app.cash.quickjs:quickjs-android:0.9.2`
содержит QuickJS 2021-03-27 (видно по строке версии в `libquickjs.so`). Версия
важна: более старый движок не разберёт классовые поля, которых в `abogus`
много.

```bash
curl -sLO https://bellard.org/quickjs/quickjs-2021-03-27.tar.xz
tar xf quickjs-2021-03-27.tar.xz && make -C quickjs-2021-03-27 qjs
# в файл: var QS = "..."; var UA = "..."; затем signer.js и вызов
./quickjs-2021-03-27/qjs --script test.js
```

Ожидаемый результат — подпись длиной 300 символов за единицы миллисекунд.
Две подписи подряд не должны совпадать: внутри есть случайные байты.

## Зачем не на Kotlin

Алгоритм целиком построен на побайтовых преобразованиях браузерного SDK:
RC4, ChaCha20, MD5, перестановки слотов, отпечаток окружения. Переносить его в
Kotlin — значит завести вторую реализацию, которую придётся сверять с первой
при каждом обновлении TikTok. Здесь же исполняется ровно та сборка, которая
проверена в браузере, и единственное, что делает Kotlin, — передаёт строку
запроса и заголовок `User-Agent`.
